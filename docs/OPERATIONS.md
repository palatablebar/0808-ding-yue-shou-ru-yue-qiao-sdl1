# 批次操作

1. 用带异常样例做阶段预览，查看列数、必填值和冲突记录。采信阶段会区分可归组坏行、无法归组坏行和跨组冲突记录。
2. 执行批次后，在「运行对账」查看逐组签发计划：`可签发`、`已签发`、`暂缓` 及每组暂缓原因，定位异常分组并核对原始记录键。
3. 在结果表选中业务组，填写复核意见后「签发该组」或「暂缓该组」。对账相符的组可逐组签发，互不阻塞；带暂缓原因的组无法签发。
4. 同一记录键在多个业务组来源中互相冲突时，牵涉的组全部暂缓，其余相符组照常签发。坏行无法可靠归组（组标识缺失或非法）时整批暂缓。
5. 多人可同时复核：各自签发互不冲突的合格组；争抢同一组时仅一方成功，其余按提示刷新重试。已签发组的金额与证据不可覆盖。
6. 修复来源文件后重新上传并执行，历史批次保留供复核。
7. 下载复核证据（`review-evidence/2`），其中逐组标明已签/暂缓状态、暂缓原因与复核意见，保存于交接记录。

单文件 256 KiB，最多 2000 条逻辑记录。容器重启后保留批次与逐组复核结论。恢复时使用原 Docker Compose 数据卷。
